# TrainDriverApp (рабочее название — «Крис»)

Android-приложение для машиниста локомотива (аналог УСАВП/ИСАВП-РТ). На экране устройства
приложение называется «Крис» (может ещё поменяться); `TrainDriverApp` — кодовое имя самого
проекта/репозитория, менять не стал, чтобы не переименовывать пакет и Gradle-модули без нужды.

## Что уже сделано (шаг 1)

Самый первый шаг: GPS показывает текущую координату в формате **км+пк**, без какого-либо
оформления экрана — просто крупный текст на чёрном фоне.

Как это работает:

1. `location/GpsLocationProvider.kt` — получает координаты через стандартный `LocationManager`
   (провайдер `GPS`), без Google Play Services и без интернета — приложение должно быть полностью
   автономным (ТЗ, раздел 2).
2. `route/RouteTrack.kt` — проецирует GPS-точку на ближайший отрезок полилинии пути и возвращает
   пикетаж (расстояние от начала маршрута в метрах).
3. `route/ChainageFormatter.kt` — переводит пикетаж в формат "км+пк" по формуле из ТЗ (раздел 7):
   `км = floor(км_отрезок) + 1`, `пк = floor(метры_в_км / 100) + 1`.
   Проверено на примерах из ТЗ: `0000.050 → 1км 1пк`, `6234.670 → 6235км 7пк`.
4. `MainActivity.kt` — запрашивает разрешение на геолокацию и выводит результат в `TextView`.

## Шаг 2: подключена реальная линия пути

Из присланного `export.geojson` (реальная выгрузка из OSM, 86 838 точек / 7850 сегментов —
совпадает с цифрами из ТЗ) вычленен и упорядочен реальный путь перегона
Хилок → Карымская → Чернышевск-Забайкальский:

- Из 7850 сегментов исходного файла (он покрывает намного больший район — вся Восточная Сибирь
  и Забайкалье, а не только наш перегон) отфильтрованы съезды/тупики/парковые пути, из оставшихся
  собран граф связности и найден путь между узлом у Хилока и узлом у Чернышевска-Забайкальского.
- Результат — `app/src/main/assets/route_hilok_chernyshevsk.json`, 5841 точка, ~640 км.
- Загружается через `route/RouteAssetLoader.kt`, используется в `RouteTrack` так же, как раньше
  использовалась заглушка — остальной код (`chainageMetersFor`, `ChainageFormatter`) не менялся.
- Сборка воспроизводима: `tools/build_route_asset.py export.geojson app/src/main/assets/route_hilok_chernyshevsk.json`
  (сам `export.geojson` в репозиторий не кладём — он большой; когда появится более точная/новая
  выгрузка, ассет пересобирается этой же командой).

### Важно: калибровка км — ПРИБЛИЗИТЕЛЬНАЯ, нужна проверка

У GPS-линии из OSM нет привязки к реальным номерам километров РЖД — только форма пути. У профиля
пути в PDF (`Хилок-Крм.pdf`, `Крм-Чернышевск.pdf` и т.д., которые ты прислал) есть реальные номера
км, но нет GPS. Пока сделано так:

- начало маршрута (ближайший к Хилоку узел линии) считается точкой **км 5930** — это число просто
  прочитано с левого края первой страницы `Хилок-Крм.pdf`, где начинается участок с станцией Хилок;
- построенная по OSM линия короче, чем разница реальных км по профилю (642.8 км против 659 км
  между Хилоком и Чернышевском) — это ожидаемо, т.к. OSM хранит сглаженную/упрощённую форму пути.
  Введена единая поправка на длину `659 / 642.8 ≈ 1.025` (`RouteTrack.HILOK_CHERNYSHEVSK_LENGTH_CORRECTION`),
  чтобы компенсировать это в среднем по всему маршруту;
- совпадение общей длины (642.8 км по факту против 659 км по профилю, расхождение ~2.5%) — хороший
  знак, что путь построен правильно (не перепутана ветка на разъезде и т.п.), но это не то же самое,
  что точная калибровка каждого пикета.

**Что нужно от тебя, чтобы довести до точности:** одна-две проверенные пары "GPS-точка ↔ реальный
км+пк" (например, встань на сигнале с известным км+пк и посмотри, что показывает телефон). По ним
можно будет поправить `HILOK_START_KM` и коэффициент коррекции и проверить, что ошибка не растёт
к концу маршрута.

Также пока не реализовано: выбор направления (чётное/нечётное) и различение правильного/
неправильного физического пути (ТЗ, раздел 3) — сейчас пикетаж всегда считается по одной линии.

## Шаг 3: разобраны постоянные ограничения скорости

Из `скорости все новые.xlsx` (набирался вручную с бумажных документов дороги, поэтому формат
неоднородный) вычленены постоянные ограничения скорости для основного пути на нашем перегоне,
для гружёных поездов серий 3ЭС5К/ВЛ85 — это данные для «ступенчатого графика скорости» (ТЗ,
раздел 7).

- Взяты 4 листа: `Хилок-КРМ`, `КРМ-Хилок`, `КРМ-Черн`, `Черн-КРМ` (по два на направление —
  чётное/нечётное, пикеты растут/убывают, см. ТЗ раздел 3). Остальные листы файла (`Хилок-ПЗВ`,
  `КРМ-Олов` и т.п.) — это другие перегоны, не наш маршрут, не трогали.
- Из каждой строки берётся диапазон км+пк (колонка «Станция/перегон») и скорость для 3ЭС5К/ВЛ85 —
  остальные колонки (скорость по стрелкам/приёмо-отправочным путям, обрывные места, проба
  тормозов, осмотр поезда, порожние вагоны) пока не трогаем, они для отдельных функций
  (пиктограммы, оповещения) и разберём их позже.
- Результат — `app/src/main/assets/speed_limits.json`, 411 диапазонов. В код ещё не подключено —
  экрана, который бы это показывал, пока нет.
- Сборка воспроизводима: `tools/parse_speed_limits.py "скорости все новые.xlsx" app/src/main/assets/speed_limits.json`.

### Важно про эти данные

- **Иерархия диапазонов.** У каждого перегона/станции есть «общая» строка на весь блок
  (например «Хилок - Гыршелун (5935 пк 3 - 5950 пк 7)» → 80 км/ч) и более узкие строки-исключения
  внутри неё (например «5942 пк 5 - 5943 пк 7» → 60 км/ч) — обе попали в список как есть. Значит,
  при использовании этих данных нужно сначала искать САМЫЙ УЗКИЙ подходящий диапазон и только
  если ни один не подошёл — брать общий. Логику выбора ещё не писал.
- **6 опечаток в исходном файле** (кириллические "З"/"б" вместо цифр "3"/"6" — например
  "6124 пк З", "б376") — скрипт их поправил, но стоит перепроверить по бумажному оригиналу:
  `6123 пк2-6124 пк3`, `6277 пк10-6279 пк3`, `6292 пк8-6293 пк3`, `6053 пк3-6014 пк9` (Могзон -
  Тайдут), `6393 пк8-6376 пк10` (Размахнино - Зубарево), `6305 пк10-6302 пк3` (Тарская -
  Карымская).
- **Битая ячейка на участке 6159 пк 2 - 6162 пк 8** (лист Хилок-КРМ, в файле вместо числа стояло
  `'S()'`) — водитель подтвердил, что там 80 км/ч; исправление зашито в `KNOWN_CORRECTIONS` в
  скрипте, со ссылкой на то, что это подтверждено по бумажному документу, а не подобрано скриптом.
- **4 строки без понятной скорости** — не попали в итоговый файл, это станционные/стрелочные
  уточнения, чья скорость лежит в другой колонке (см. ниже про «Путь 4» и т.п.).
- **51 строка вида «Путь 4», «стр. №37», «съезд 5-7»** — это уточнения скорости для конкретного
  станционного пути/стрелки, без своего диапазона км+пк (он берётся из строки-заголовка станции
  выше). Не попали в файл — они не нужны для скорости по ходу главного пути, пригодятся позже для
  вкладки станций/путей, если понадобится.

## Сборка

Проект — стандартный Gradle/Android Studio проект (Kotlin, minSdk 26).

```
./gradlew assembleDebug
```

Открыть в Android Studio: `File → Open` → выбрать папку проекта.

> В текущей среде разработки (песочница) нет доступа к `dl.google.com`/`maven.google.com`, поэтому
> здесь нельзя скачать Android SDK и собрать APK — соберите проект в Android Studio на своей
> машине.

`app/src/test/.../ChainageFormatterTest.kt` и `RouteTrackTest.kt` — юнит-тесты на формулу

./gradlew testDebugUnitTest
